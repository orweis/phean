# OAuth Sign-In for MCP Agents Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A standard MCP client connects to `/mcp` with only the URL; a person signs in and approves in one dialog (agent name, one workspace, level, lifetime), and the agent works without a fixed key.

**Architecture:** Better Auth's `mcp()` plugin handles the OAuth protocol. Phean's `agents` row stays the source of truth: the token only carries an agent id, and every request loads that row to decide tenant, level, expiry and cutoff. `phn_` keys keep working through the same `AgentPrincipal`.

**Tech Stack:** Next.js 16, Better Auth 1.7.17 (`@better-auth/mcp`, `@better-auth/cimd`, `jwt` plugin), `mcp-handler` 2.3.0, Drizzle, PGlite in tests, Vitest, Playwright.

**Spec:** [docs/superpowers/specs/2026-11-05-mcp-oauth-design.md](../specs/2026-11-05-mcp-oauth-design.md)

## Global Constraints

- Work on branch `claude/mcp-oauth`. Never stage `src/phean/`, `tests/__pycache__/` or `uv.lock`; they are the owner's untracked files. Add files by exact path.
- `pnpm check` passes before every commit. Run `pnpm build` when touching routes, layouts or module-load imports, and `pnpm test:e2e` after UI changes.
- Tenant comes only from a verified credential, via the `agents` row, never from a token claim or tool input.
- `goal:decide` stays human-only at every level.
- Levels: `read`, `write` (default), `admin`. Lifetimes: 1, 7, 30 (default), 90, 365 days. No "never" option.
- Access tokens last 1 hour. Refresh token reuse interval is 0 unless Task 9 shows real clients breaking on concurrent refresh.
- Migrations stay compatible with the previous release. Existing agents become `authKind: "key"`, `accessLevel: "write"`.
- Log changes through `recordEvents` inside `inTransaction`. Follow `DESIGN.md` for all UI.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A forged dialog POST (workspace the person isn't in, or a level above their role) is refused and creates nothing. Test in Task 5.
2. Double-clicking Allow, or two tabs approving at once, leaves one agent. Test in Task 3.
3. The session ends while the dialog is open: Allow returns to sign-in and then back to the same dialog, not an error. Test in Task 5.
4. A hostile client name (markup, 10,000 characters) renders as plain text and is cut to `LIMITS.name` in the prefill. Test in Task 5.
5. An approver leaving kills only OAuth agents they approved, never fixed keys they issued. Test in Task 3.
